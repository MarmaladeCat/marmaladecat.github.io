04 · 认识 OpenASR

一个负责桌面输入，一个负责识别服务接入。让语音进入日常工作，需要它们各司其职。

详细教程分为三篇：软件介绍与使用、安装与配置、Portal 上下游接入配置。更多文章见OpenASR 分类。

这篇文章简单介绍我目前的两个开源项目：OpenASRInput 和 OpenASRPortal。它们围绕同一件事展开：把说出来的话，变成可以在电脑上使用的文字。

ASR 是 Automatic Speech Recognition，也就是自动语音识别。但从识别出一句话，到把它送进正在使用的编辑器或聊天窗口，中间还有音频采集、结果预览、输入法对接和服务配置等工作。这两个项目分别负责其中的不同部分。

OpenASRInput：让语音成为输入方式

OpenASRInput 是面向 Windows 和 Linux 的系统级语音输入工具。它采集麦克风音频，经由 OpenASRPortal 获取识别结果，提供预览，并将文字提交到当前输入目标。

在 Linux 上，它支持 IBus、Fcitx5，以及 X11 下的 Fcitx4；在 Windows 上，使用独立的原生桥接。它关注的是桌面端的输入体验，让语音识别结果能够进入实际使用的应用。

如果你想用口述的方式写下一段笔记、起草文字或输入消息，可以从这个项目开始了解。Input 需要连接本机或远程的 Portal，并配置对应的客户端识别 Key。

OpenASRPortal：统一连接识别服务

OpenASRPortal 是客户端与识别服务之间的接入层。它提供统一的 HTTP / WebSocket v1 接口，上游可连接豆包、百炼、Soniox 和 Boson 等云端语音识别服务。

除了转接识别请求，它还提供会话、上游档案、客户端 Key、热词和配额管理，以及用于配置服务的管理网页。客户端通过 Portal 接入，识别服务的配置则集中在 Portal 一侧。

Portal 本身不是语音识别模型。实际识别由配置的上游服务完成，选择不同的上游可以使用对应的识别能力。

两个项目怎样配合？

可以把 Input 理解为桌面上的输入入口，把 Portal 理解为连接识别服务的中间层。一次语音输入大致经过以下过程：

  1. 采集：OpenASRInput 从麦克风获取音频。
  2. 识别：音频经由 OpenASRPortal 发送给配置的上游识别服务。
  3. 返回：识别结果通过 Portal 返回 Input。
  4. 输入：Input 展示预览，并将文字提交到当前输入目标。

这样的分工让桌面输入与服务接入可以分别维护。除了搭配 Input 使用，开发者也可以按照 Portal 的 API 文档，为其他客户端接入语音识别能力。

从哪里开始体验？

建议先阅读两个仓库的中文使用手册，确认自己的系统环境与安装方式：

  • Portal 使用手册：准备本机或远程服务，设置管理密码、添加上游，再创建客户端 ASR Key。
  • Input 使用手册：安装输入端，配置 Portal 地址与 Key，并按平台说明完成输入桥接设置。

安装包与后续更新可以查看 Input Releases 和 Portal Releases，具体支持情况以对应版本文档为准。
